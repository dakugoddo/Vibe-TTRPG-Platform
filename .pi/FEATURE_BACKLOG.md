# Vibe TTRPG Platform: feature backlog

> Дата обновления: 2026-05-31
> Назначение: единая очередь новых функций для triage, планирования вертикальных срезов и защиты от распыления.

## Приоритеты

- `F0` — фундаментальная схема/миграция, без которой следующие функции будут хрупкими.
- `F1` — основной игровой workflow для ГМа/игроков.
- `F2` — важное ускорение работы или quality-of-life.
- `F3` — полировка, эксперимент или визуальное улучшение.

## Правило обработки

- [x] Сначала feature triage: записать фичу, модуль, приоритет, batch key, зависимости и acceptance criteria.
- [x] Проверить, не существует ли уже фундамент фичи; если существует — доделывать существующий контур.
- [x] `F0` и фичи, меняющие `.md`, sync, permissions или файловую систему, начинать с design-doc в `.pi/docs/`.
- [x] Группировать `F2/F3` по модулю и закрывать тематическими срезами.
- [x] После реализации обновлять этот файл, `.pi/DEVELOPMENT_PLAN.md`, QA-документ и делать отдельный commit.

## Зависимости

- `FEAT-WIKILINK-001` опирается на core `FEAT-ENTITY-ID-001`; следующий риск - ручная проверка миграции старых файлов без `id` на копии мира.
- Будущие атаки, предметные эффекты и статусы должны использовать `FEAT-ROLL-001`, а не прямой `diceParser` или `Math.random`.
- `FEAT-AUDIO-001/002` теперь считаются foundation/prototype; финальное развитие идёт через `FEAT-AUDIO-003`, чтобы не раздувать `AssetBrowser` и не закреплять неверное место UI.
- `FEAT-AUDIO-003` зависит от `FEAT-MODULES-001`, `FEAT-SETTINGS-001`, `FEAT-ROLES-PLAYERS-001`, stable asset IDs из `FEAT-ASSETS-001`, общего `audioPlayback` service и решения по внешним audio source extensions.
- `FEAT-AUDIO-004` должен идти раньше сложных внешних источников: локальный `music` player с timeline является базой для SoundCloud/YouTube extensions.
- `FEAT-AUDIO-SOURCES-001` не должен попадать в core audio MVP: YouTube и SoundCloud развиваются как extensions после отдельного product/API gate.
- `FEAT-NOTIFICATIONS-001` должен идти до `FEAT-ASSET-UPLOAD-APPROVAL-001`: approval/progress нельзя надёжно строить поверх обычного чата.
- `FEAT-MODULES-001` должен предшествовать крупным отключаемым функциям: audio player, будущие 3D/Steam-friendly modules, внешние интеграции и player-delegated tools.
- `FEAT-EXPLORER-001` требует server-side host API: браузер сам по себе не может открыть и выделить файл в Windows Explorer.
- `FEAT-CANVAS-NAV-001` нужно решить до полноценного session director/workbench: от этого зависит, является ли active canvas глобальным состоянием сессии или личным состоянием каждого клиента.
- `FEAT-CANVAS-EXCALIDRAW-001` должен идти до больших визуальных canvas-фич: line binding и snap model влияют на формат draw elements и undo/redo.
- `FEAT-CANVAS-TOKENS-001` зависит от `FEAT-ASSETS-001`, `FEAT-ENTITY-ID-001` и permission helper: canvas token должен ссылаться на entity по ID и не раскрывать закрытые сущности.
- `FEAT-ENTITY-FILENAME-001` зависит от стабильных entity IDs и должен идти через `renameManager`/file watcher, чтобы переименование файлов не ломало ссылки и вложенные папки.
- `FEAT-ENTITY-DROP-001` должен предшествовать `FEAT-BULK-OPS-001`: массовые операции не стоит делать до единого drop/action contract.
- Будущий native multi-window/multi-monitor workflow зависит от `FEAT-PLATFORM-TAURI-001`; browser popout не считать ближайшим фундаментом.
- `FEAT-ENTITY-PERMISSIONS-001` зависит от `FEAT-ROLES-PLAYERS-001` и будет влиять на canvas `i`, double-click open и личные player-owned сущности.
- `FEAT-SETTINGS-001` зависит от текущей доверенной permission model и будущего role contract; базовая роль должна быть неизменяемой и применяться ко всем подключившимся.
- `FEAT-SEARCH-001` зависит от стабильных entity IDs и текущего EntityDatabase tree-search; foundation уже расширяет существующий контур, не создавая параллельную панель поиска.
