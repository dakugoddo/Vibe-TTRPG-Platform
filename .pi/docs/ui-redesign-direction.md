# UI redesign direction

> Дата: 2026-05-21  
> Статус: draft для `FEAT-UI-001`.

## Проблема

Интерфейс уже функционален, но выглядит не как цельная VTT-платформа:

- часть элементов живёт в общем glass/dark языке, часть выглядит как временные кнопки;
- модульные блоки сущностей визуально однообразны и слабо показывают назначение;
- стандартные scrollbars и hover-only create buttons ломают ощущение полированного инструмента;
- важные действия иногда выглядят слабее вторичных действий.

## Дизайн-направление

Vibe TTRPG Platform должна ощущаться как рабочий стол ГМа: плотный, быстрый, немного мистический, но без лендинговой декоративности.

Ключевые принципы:

- **Сессионная плотность**: больше полезной информации в первом экране, меньше огромных декоративных карточек.
- **Ясные affordance**: кнопки создания, броска, открытия и импорта видны сразу, а не только на hover.
- **Модульная выразительность**: блоки персонажа, предмета, способностей, ресурсов и атак имеют свой акцент, но общий каркас.
- **Тактильный glass**: мягкий dark glass, тонкие borders, аккуратные inner shadows, без случайных ярких пятен.
- **Без монотонной палитры**: не уходить целиком в синий/фиолетовый; типы сущностей уже дают здоровые акценты.
- **Тема как данные**: будущая смена палитры должна идти через theme tokens/presets, а не через ручное переписывание компонентов. Подробный draft: `.pi/docs/settings-theme-roles.md`.

## Срезы

### Slice 1: UI hygiene

- Нормализовать `Import .md` button.
- Скрыть native scrollbars или привести их к теме.
- Сделать create plus постоянно видимым.
- Проверить `min-h-0`/overflow в drawers и windows.

### Slice 2: Entity module kit

- Общий header pattern для блоков: icon, title, count/status, primary action.
- Unified tab strip для CharacterSheet/ObjectSheet/AbilitySheet. Выполнено базово через `SheetTabs`.
- Плотные stat tiles без горизонтального overflow.
- Empty states как небольшие рабочие подсказки, а не большие заглушки.

### Slice 3: GM workbench polish

- Asset browser, audio controls, context menu actions и quick-create должны выглядеть как одна панель инструментов.
- RightDrawer и LeftDrawer используют общий плотный header pattern: иконка, заголовок, подзаголовок, компактная кнопка сворачивания; LeftDrawer сохраняет отдельный selector игроков для GM.
- Важные GM-only действия помечать тонко, но явно.
- Hover states оставлять как усиление, а не как единственный способ найти действие.

## Acceptance criteria

- [ ] На основных окнах нет системных scrollbars, которые выбиваются из темы.
- [ ] Кнопки создания сущностей всегда доступны визуально.
- [ ] Import/export/context-menu actions имеют одинаковый визуальный вес.
- [x] Character/Object/Ability sheets используют совместимый tabbed layout.
- [x] При ширине окна 400-600 px tab strip не показывает системную горизонтальную полосу; ручная визуальная QA ещё нужна.
- [x] Боковые шторки используют совместимый header pattern; ручная визуальная QA на 400 px ещё нужна.
- [ ] UI остаётся плотным и пригодным для быстрой работы во время игры.
- [ ] Цветовая тема описана токенами и может стать пользовательским preset без массовой правки JSX.
