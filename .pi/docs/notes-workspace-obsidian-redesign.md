# Notes workspace: Obsidian-like redesign

> Обновлено: 2026-06-07
> Статус: первый рабочий срез реализован

## Задача

Режим заметок должен быть похож на Obsidian по рабочей модели, но не копировать его один в один. В Eternity Table сущность является не только Markdown-файлом, но и контейнером для других сущностей, игровых свойств, тегов и прав доступа.

## Проверенная модель Obsidian

Ориентиры из официальной документации Obsidian:

- Workspace строится вокруг центральной рабочей области, вкладок, боковых панелей и дополнительных связанных views.
- Tabs можно разделять на группы/панели и переносить между ними.
- Для заметки существуют режимы редактирования и чтения; в редактировании есть live/source-подход.
- Backlinks, Outline и Graph являются связанными представлениями вокруг активной заметки.
- File explorer представляет vault как файловую иерархию.

Источники:

## Текущий контракт реализации

- В контексте режима заметок "окно", "модуль" и "вкладка" являются одним пользовательским понятием: рабочая вкладка. `Audio`, `Vault`, `Search`, `Context`, `Graph`, `Notifications` и вкладки сущностей отличаются контентом, но должны одинаково открываться, фокусироваться, закрываться, перетаскиваться, объединяться во вкладки и делиться edge-drop.
- `NotesWorkspace.tsx` рендерит три зоны: vault/entity tree слева, tab/split editor в центре, linked context справа.
- `notesWorkspaceLayout.ts` хранит чистую локальную модель editor leaves: tab groups, split-панели, resize ratios и leaf-open поведение.
- `notesWorkspaceStore.ts` сохраняет layout в localStorage и мигрирует legacy `markdown` view в `preview`.
- Режимы вкладки: `source`, `preview`, `split`, `entity`, `outline`, `backlinks`, `graph`.
- `source` и `split` редактируют только `entity.description` через `yjsStore.updateEntity`.
- Контент редактируется только если `canModifyEntity(...)` разрешает запись; иначе textarea работает как read-only.
- Вложенные сущности показываются как часть entity context, а не как отдельный файловый формат.
- Дерево vault хранит локальное состояние раскрытых веток и автоматически раскрывает родителей активной сущности.
- Клик по новой сущности открывает ее как отдельный editor leaf рядом с активным leaf; повторный клик по уже открытой сущности не плодит дубликаты и фокусирует существующий leaf, при необходимости меняя view.
- Wiki autocomplete включается только в редактируемом `source/split` textarea; для read-only сущностей он не должен открываться и не должен давать обход прав.
- Режим `graph` в этом срезе является локальной сводкой связей активной сущности: входящие ссылки, текущая сущность, исходящие ссылки. Полноценный canvas-like graph view остается отдельным будущим срезом.
- Notes mode использует собственный dock shell: left ribbon, vault pane, editor pane и context pane занимают экран без внешних canvas/HUD отступов. Глобальные canvas-кнопки, `HudBar`, `RightDrawer` и canvas-only hotkey help не должны рендериться поверх режима заметок.
- Split-панели должны быть обратимыми: у каждой панели, кроме последней оставшейся, есть `closePane`, который удаляет только локальную панель layout и не трогает entity-файлы.
- Drag/drop рабочих вкладок должен быть pointer-driven и различать feedback по действию, без browser HTML ghost preview. Перетаскивание на левый/правый/верхний/нижний край другой рабочей вкладки показывает тонкую edge-line и создаёт split; точное перемещение внутри tab strip показывает вертикальную insertion-line; drop в центр контента переносит вкладку в существующую tab group и показывает полноразмерный dashed overlay объединения. Split-кнопки в шапке leaf не нужны.
- Vault в notes mode обязан сохранять группировку сущностей по типам, как database drawer в canvas mode, но single-click по строке всегда открывает/фокусирует сущность. Раскрытие детей делается только отдельной стрелкой, а не кликом по строке.
- Notifications в notes mode не должны рендериться floating-кнопкой поверх редактора. Они показываются как встроенный context-pane блок; глобальный floating notification center остается canvas-only.

## Правила для следующих срезов

- Не возвращать управление screen windows в основной режим заметок. Плавающие окна остаются отдельным canvas/screen workflow.
- Не создавать world-shared workspace layout без отдельного product/architecture gate.
- Не менять `.md`/YAML формат ради UI режима.
- Если нужен полноценный Obsidian-like notes mode, расширять текущую схему: editor tabs, linked panes, search, outline/backlinks, graph, свойства и children.
- Если добавляются новые глобальные модули app shell, проверять их отдельно в `canvas` и `notes`: в `notes` они должны быть встроены в ribbon/status bar или явно скрыты, а не перекрывать editor/vault/context.
- Не добавлять split-only кнопки без обратного действия и drag affordance. Любая операция, которая создает новую pane/group, должна иметь понятный способ закрыть pane и визуально показать drop target.
- Не смешивать два действия в строке entity tree: row click = open/focus, chevron click = expand/collapse. Это правило общее для canvas drawers и notes vault.
- Native multi-window и multi-monitor открытие сущностей делать после desktop gate, не внутри browser-only NotesWorkspace.

## Ближайшая ручная QA

- Открыть режим `Заметки`.
- Найти сущность в vault слева, открыть ее.
- Проверить переключатели `Редактор`, `Просмотр`, `Два вида`, `Данные`, `Оглавление`, `Связи`, `Граф`.
- Проверить, что вложенные сущности отображаются справа и в режиме `Данные`.
- Проверить, что игрок без прав видит read-only состояние и не может сохранить `description`.
- Раскрыть/свернуть несколько веток vault, открыть вложенную сущность и убедиться, что ее родительская цепочка раскрыта.
- Открыть несколько разных сущностей из vault/search/ссылок: каждая новая сущность должна появиться отдельным editor leaf рядом с активным; повторный клик по уже открытой сущности должен фокусировать ее без дубля.
- В редактируемой заметке набрать `[[` и проверить подсказки wiki-ссылок; в read-only заметке подсказки не должны открываться.
- В режиме `Граф` проверить центральную карточку сущности, счетчики входящих/исходящих ссылок и переход по соседним сущностям.
- Проверить, что в notes mode нет больших пустых полей по краям, canvas HUD справа не перекрывает context pane, а старые левые плавающие кнопки заменены встроенным ribbon.
- Перетащить вкладку или заголовок editor leaf в центр другого leaf: сущности должны объединиться в одно окно с вкладками; перетащить на край другого leaf: должна появиться подсветка будущего split, после drop должна появиться новая панель в выбранной стороне. Browser ghost preview и старые split-кнопки не должны появляться.
- Закрыть лишнюю панель крестиком панели и убедиться, что split схлопнулся, а сущность можно заново открыть из vault.
- Проверить в canvas drawer и notes inventory/vault: один клик по сущности открывает/фокусирует ее, а сущность с детьми раскрывается только по стрелке.
- Проверить, что уведомления в notes mode находятся внутри context-pane блока и не перекрывают редактор сверху.
