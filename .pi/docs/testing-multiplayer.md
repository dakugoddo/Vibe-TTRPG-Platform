## Подготовка Виртуальной Сети (Hamachi / RadminVPN)

1. Установите одинаковую программу для LAN-эмуляции (Hamachi или RadminVPN).
2. Хост (ГМ) создаёт новую сеть с паролем.
3. Игрок подключается к этой сети.
4. В приложении рядом с именем хоста появится **IPv4-адрес** (например, `25.55.120.14`). Запиши его.

---

## Запуск Серверов (делает только Хост)

1. Запусти проект: `start.bat`
   - Vite dev server: порт 5173
   - Express сервер: порт 3001
2. Убедись, что брандмауэр Windows не блокирует порты `5173` и `3001`.

---

## Вход в игру

**Хост (ГМ):**
- Открой `http://localhost:5173`
- Выбери роль Host, создай/открой мир

**Игрок:**
- Открой браузер, введи `http://<IP_ХОСТА>:5173` (например `http://25.55.120.14:5173`)
- Выбери роль Player, введи имя
- **Игроку не нужно ничего устанавливать!**

## Тест №1: Базовая синхронизация и курсоры

1. Игрок и хост видят перемещение курсоров друг друга (цветные кружки + имена).
2. Хост рисует квадрат — игрок видит мгновенно.
3. Игрок рисует круг — хост видит мгновенно.
4. G+клик = пульсирующий пинг (виден всем).

### Network regression smoke check for `BUG-MULTIPLAYER-001`

1. Start host through `start.bat`, then connect a second browser/client through the Radmin/Hamachi IP, not `localhost`.
2. Watch the server console during first sync.
   - Expected: no Node process crash, no raw `RangeError: Max payload size exceeded`; if a stale oversized client packet appears, server logs a warning and keeps running.
3. Open the root canvas with several image/GIF assets.
   - Expected: assets load through `/api/assets/file?path=...`, canvas sync remains usable, and GIF assets animate.
4. Move the mouse continuously for 20-30 seconds on both clients.
   - Expected: cursors are responsive without flooding the log; awareness is throttled around 20 updates/sec.
5. Move one canvas object and release it.
   - Expected: the other client receives the final position without a multi-second freeze.
6. Leave the session open for 2 minutes.
   - Expected: no repeating startup-style `GET/PUT/rename-path` storm for unchanged entities; rename-path calls happen only after real title changes.
7. As Player, navigate the canvas with mouse controls.
   - Expected: plain wheel zooms around the pointer; holding the middle mouse button pans the canvas even without edit rights.
8. Open `Файлы` on the Host while several MP3 files exist in `assets/`.
   - Expected: opening the all-files view should not immediately request every MP3 for duration metadata; duration probing happens only after switching to the audio filter.

## Тест №2: Undo/Redo (Selective Undo)

1. Хост рисует квадрат.
2. Игрок перекрашивает квадрат в **красный**.
3. Хост **передвигает** красный квадрат.
4. Хост нажимает `Ctrl+Z`.
   - **Ожидаемый результат:** Квадрат возвращается в центр (отменилось движение хоста), но остаётся **красным** (цвет игрока не отменился).
5. Хост нажимает кнопку undo в верхней панели.
   - Ожидаемый результат: результат такой же, как у `Ctrl+Z`, кнопка становится disabled, если undo stack пуст.
6. Хост нажимает `Ctrl+Shift+Z`, `Ctrl+Y` или кнопку redo.
   - Ожидаемый результат: отменённое действие возвращается, redo stack корректно очищается после новой правки.
7. Проверь line object: создай линию, перетащи её с включённой сеткой/snap, затем `Ctrl+Z`.
   - Ожидаемый результат: линия возвращается по исходной траектории; её точки не "уезжают" из-за старого bbox.

## Тест №8: GM-only и доверенная privacy модель

1. Создай или открой заметку с блоком/контентом `gm-only`.
2. Проверь её под ролью Host/GM.
   - Ожидаемый результат: ГМ видит скрытый контент.
3. Проверь ту же заметку под ролью Player.
   - Ожидаемый результат: игрок не видит GM-only контент в интерфейсе.
4. Проверь, что игрок не видит GM-базу и чужие user-сущности в обычном UI.

Важно: это доверенная privacy модель. Она проверяет корректное UI-скрытие, но не является криптографической защитой от технически любопытного клиента.

## Тест №10: База сущностей и быстрые действия

1. В `EntityDatabase` введи часть имени, типа, описания, тега или свойства.
   - Ожидаемый результат: список фильтруется, найденные вложенные сущности показываются вместе с родителями. Запросы по структуре вроде `атлетика 3`, `скрытность 2`, `hp 7` находят сущности по расплющенным `properties`, а не только по видимому имени.
1.1. Проверь search summary под полем поиска.
   - Ожидаемый результат: видно число прямых совпадений и число сущностей, показанных вместе с контекстом дерева; facet-кнопки по типам переключают текущую вкладку без потери запроса.
1.2. Открой найденную ветку.
   - Ожидаемый результат: совпавшие термины подсвечены в имени/snippet, а под типом сущности видно поле совпадения: имя, описание, свойства, теги, тип, id или база.
1.3. Проверь расширенный query syntax: `type:character`, `тип:персонаж`, `tag:<имя>`, `#<тег>`, `db:gm`, `"точная фраза"` вместе с обычными словами.
   - Ожидаемый результат: фильтры сужают прямые совпадения без потери дерева контекста; фразы ищутся как цельный текст; обычные слова продолжают искать по имени, описанию, тегам и `properties`.
1.3a. Проверь property-фильтры: `prop:hp.current>=7`, `prop:skills.stealth.base=2`, `свойство:атлетика=3`.
   - Ожидаемый результат: фильтры работают по вложенным `properties`, поддерживают `=`, `:`, `>`, `>=`, `<`, `<=`, а совпадение помечается как поле `свойства`.
1.4. Введи поисковый запрос, подожди около секунды, очисти поле и проверь чипы `Недавние`.
   - Ожидаемый результат: последний запрос появляется в локальной истории, клик по чипу восстанавливает поиск, `Сброс` очищает список и `localStorage`.
1.5. В активном поиске нажми `Сохранить`, очисти поле и проверь чипы `Сохранённые`.
   - Ожидаемый результат: сохранённый запрос остаётся отдельным чипом, клик восстанавливает поиск, кнопка `x` удаляет только этот сохранённый запрос.
2. Найди предмет с дочерней атакой или создай такую связку.
   - Ожидаемый результат: стрелка раскрывает дочерние сущности; при активном поиске ветка раскрыта автоматически.
3. Открой контекстное меню сущности и проверь `Дублировать`.
   - Ожидаемый результат: копия появляется рядом с оригиналом, дочерние элементы копируются, новое окно копии открывается.
4. Проверь `Копировать [[ссылку]]`.
   - Ожидаемый результат: в буфер попадает canonical wiki-ссылка вида `[[20260521112233444]]`; в UI/renderer она открывает нужную сущность по ID.
4.1. Под ролью ГМа/Host проверь `Показать в проводнике`.
   - Ожидаемый результат: Windows Explorer открывается и выделяет `.md` файл сущности. У Player/browser-only клиента пункт не показывается.
5. Открой контекстное меню персонажа и создай дочерний предмет или компетенцию.
   - Ожидаемый результат: новая сущность появляется внутри персонажа, наследует базу/owner marker и открывается в окне.
6. Открой контекстное меню предмета и создай дочернюю атаку.
   - Ожидаемый результат: атака появляется внутри предмета и доступна через раскрытие ветки/поиск.
7. Открой персонажа или user-сущность, которую текущий игрок не может редактировать, и проверь блок компетенций.
   - Ожидаемый результат: кнопки добавления, изменения ранга и удаления скрыты, но бросок компетенции и открытие окна доступны.
8. Открой read-only предмет и read-only атаку.
   - Ожидаемый результат: значения можно прочитать и связанные сущности открыть, но поля не редактируются, свойства не добавляются/удаляются, атаки нельзя создать, перетащить или удалить.
9. Открой read-only сущность в окне и проверь заголовок, описание, заметки персонажа и изображение.
   - Ожидаемый результат: rename/delete, edit description/notes, hidden tags и image edit недоступны; Markdown, wiki-ссылки и обычное чтение работают.
10. Открой read-only персонажа на вкладке навыков.
   - Ожидаемый результат: кнопки изменения ранга скрыты, но бросок навыка через Roll Engine доступен при положительном ранге.
11. Открой read-only персонажа на вкладке inventory.
   - Ожидаемый результат: предметы читаются, но equip, quantity, delete и drag/drop недоступны; при копировании/переносе в owned inventory дочерние атаки сохраняют owner marker.
12. Открой read-only персонажа на вкладке stats.
   - Ожидаемый результат: статы, раны, мощь и статусы читаются, но не меняются; чат не получает ложные события ран/статусов.
13. Открой canvas или сущность на canvas, которую текущий игрок не может редактировать.
   - Ожидаемый результат: drawing/fog/style controls скрыты или не сохраняют изменения; undo/redo не меняет read-only canvas; read-only портал нельзя перетащить или удалить; read-only токен нельзя перетащить, но его окно можно открыть.
14. Открой сущность с родителем, дочерними сущностями, тегами или входящей `[[wiki-ссылкой]]`.
   - Ожидаемый результат: в окне сущности появляется блок `Links`; ссылки открывают доступные сущности, а GM-only и чужие user-сущности не появляются у игрока.
15. Сделай правый клик по заголовку окна сущности.
   - Ожидаемый результат: у редактируемой сущности доступны rename/duplicate/copy/delete, а read-only сущность не показывает edit-меню и может быстро скопировать `[[wiki-ссылку]]`.
16. В том же меню у персонажа создай предмет/компетенцию/способность, а у предмета создай атаку.
   - Ожидаемый результат: новая дочерняя сущность создается внутри родителя, наследует database/owner marker и сразу открывается отдельным окном.
17. Открой персонажа на вкладке `Способности`, создай способность, задай `Формула` вроде `1d6+1`, нажми кнопку броска.
   - Ожидаемый результат: способность отображается как дочерняя ability-сущность, окно способности имеет вкладки `Параметры` и `Описание`, поля `Стоимость`, `Формула`, `Дистанция`, `Область` сохраняются, бросок уходит в чат через Roll Engine.
17.1. Открой предмет -> вкладку `Атаки`, создай/открой атаку, задай `Формула броска` вроде `1d20+2` или `2d6`, нажми кнопку с кубами.
   - Ожидаемый результат: формула сохраняется в `properties.diceFormula`, бросок из окна атаки и быстрый бросок из списка атак предмета уходят в чат через Roll Engine.
18. Открой персонажа на вкладке `Ресурсы`, создай ресурс, измени название/current/max, нажми кнопки `+/-`.
   - Ожидаемый результат: `properties.resources` сохраняет счетчик, current не уходит ниже 0 и не превышает max, read-only персонаж не показывает edit-controls.
19. На canvas создай несколько draw elements, выбери `...` -> `Лассо`, обведи несколько элементов, включая старт жеста поверх одного из них.
   - Ожидаемый результат: после отпускания мыши выбранные элементы остаются выделенными, инструмент переключается в `select`, а синхронизация canvas data не создает лишних persistent writes до завершения действия.
20. Открой предмет.
   - Ожидаемый результат: `Параметры`, `Атаки` и `Описание` находятся в отдельных вкладках общего стиля; описание редактируется только во вкладке `Описание`, а generic description block над предметом не дублируется.
21. Проверь базу сущностей.
   - Ожидаемый результат: кнопка `Импорт .md` визуально совпадает с темой, plus для создания категорий виден без hover, горизонтальные tab-scrollbars не показывают системную полосу.
22. Открой правую шторку -> вкладку `Файлы`.
   - Ожидаемый результат: Host видит рекурсивный список файлов из `assets/`, фильтры по типам, сортировку по имени/новизне/размеру/типу, preview изображений, размер файла, длительность audio assets, стабильный internal `asset.id` в данных API, кнопку `Показать в проводнике` и upload-кнопку. Player/browser-only клиент видит аккуратное сообщение, что браузер файлов доступен Host/ГМу. На клиенте, подключённом по IP, изображения грузятся с IP хоста, а не с `localhost`.
22.1. Открой сущность -> `Изменить фото` -> выбери существующее изображение из подпапки `assets/`.
   - Ожидаемый результат: список берётся из рекурсивного asset index, сохраняется `asset.path`, картинка отображается через host-aware `/api/assets/file?path=...`.
22.2. Перетащи image asset из вкладки `Файлы` на canvas.
   - Ожидаемый результат: на canvas создаётся image draw element с правильным размером и выделением; в данных элемента хранится `imageAssetPath`, а не hardcoded `localhost` URL; у игрока, подключённого по IP, картинка отображается через host-aware URL.
22.3. Выбери tool `Изображение` или перетащи новый image file напрямую на canvas.
   - Ожидаемый результат: на Host файл загружается в `assets/`, новый canvas element хранит `imageAssetPath`, а после обновления вкладки `Файлы` этот файл доступен в списке и в `Изменить фото` сущности.
22.3a. Выбери tool `Изображение`, кликни по пустому canvas и выбери уже существующую картинку из picker.

## Тест №10.3: GM Audio Desk

1. Под ролью Host/ГМ открой нижний аудио-док кнопкой `Звук`.

2. Выбери канал `SFX`, найди audio asset и нажми `+`.

4. Включи `Игрокам`, включи `Звук сессии` на player-клиенте и снова нажми play/stop.

6. Измени громкость канала в микшере.
   - Ожидаемый результат: громкость сразу влияет на уже играющий звук соответствующего канала, работает для media/Web Audio playback и сохраняется локально.
7. Пока играет длинный трек, переключай правую шторку между `Хранилище`, `Файлы`, `Чат и броски`.
   - Ожидаемый результат: playback продолжается, потому что аудио-пульт не живёт внутри вкладки.

## Известные ограничения

- Undo-история сбрасывается при переключении канвасов (Sub-documents).
- Drag во время перемещения токенов сохраняется через CRDT — при большом количестве одновременных перемещений возможна задержка.
- Настоящая приватность требует отдельных sync boundaries; сейчас принята доверенная модель с UI-скрытием.
- `fogReveals` исторически называется reveal-полем, но текущая модель может хранить dark patches. Переименование лучше делать отдельной миграцией.

### Notifications and upload progress

1. Под Host/GM открой `Файлы` и загрузи небольшой asset.
   - Ожидаемо: появляется toast/уведомление с прогрессом и успешным завершением.
2. Открой центр уведомлений через кнопку с колокольчиком.
   - Ожидаемо: видна история уведомлений; завершённые записи можно очистить.
3. Под player-клиентом открой `Файлы`, нажми `Запросить крупную загрузку` и выбери файл больше `50 MB`.
   - Ожидаемо: у игрока появляется pending-уведомление `Запрос отправлен ГМу`; реальная передача файла не начинается.
4. На GM-клиенте открой центр уведомлений.
   - Ожидаемо: виден запрос с именем игрока, названием файла, размером и кнопками `Одобрить` / `Отклонить`.
5. Нажми `Одобрить`, затем повтори сценарий и нажми `Отклонить`.
   - Ожидаемо: при `Отклонить` у игрока и ГМа локальное уведомление меняет статус на `rejected`, файл не грузится.
6. Повтори сценарий, нажми `Одобрить` и дождись окончания загрузки.
   - Ожидаемо: player-клиент начинает загрузку на host, у игрока и ГМа виден progress, затем статус `Файл загружен`. Файл появляется в `assets/` на хосте после обновления списка. Файлы больше текущего лимита `250 MB` пока требуют будущий chunked upload.
7. Под Host/GM перетащи небольшой image-файл прямо на canvas.
   - Expected: a local upload progress notification appears immediately, the image is inserted only after `/api/assets/upload-binary` succeeds, and the canvas element uses `imageAssetPath` instead of inline `data:`.
8. Под player-клиентом перетащи image-файл больше `50 MB` прямо на canvas.
   - Expected: player sees a pending GM approval notification, GM can approve/reject in notification center, upload progress appears after approval, and the image appears on canvas only after the uploaded asset URL loads.

### Multiplayer latency regression

1. Запусти Host через IP-сценарий, которым обычно подключается второй клиент.
2. Подключи player-клиент через IP/Radmin/Hamachi.
3. На обоих клиентах подвигай мышью по canvas 15-20 секунд.
   - Ожидаемо: remote cursor двигается без секундных залипаний. Cursor awareness теперь ограничен примерно 20 обновлениями/сек, поэтому движение может быть чуть менее “жидким”, но не должно забивать sync.
4. На Host перетащи canvas object и отпусти.
   - Ожидаемо: remote-клиент получает итоговую позицию после отпускания без большой задержки.
5. Во время player upload approval/progress повтори шаги 3-4.
   - Ожидаемо: progress notifications не должны ломать canvas sync; progress throttled и не пишет в Yjs на каждый network progress event.
6. Перезайди в комнату после нескольких завершённых/отклонённых upload-заявок.
   - Ожидаемо: старые resolved session notifications не копятся бесконечно; GM/Host чистит их по TTL/count.
7. Если задержка остаётся сильной без активной загрузки файлов, записать условия: размер мира, открыт ли AssetBrowser, есть ли GIF/video на canvas, сколько clients, примерная задержка в секундах.
