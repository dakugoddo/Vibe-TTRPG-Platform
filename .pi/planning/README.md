# Хранилище планирования Eternity Table

Это папка, где хранится **только актуальная рабочая информация** о будущем проекта. Она написана для владельца проекта, а не как технический отчёт для программиста.

## С чего начинать

1. [`../DEVELOPMENT_PLAN.md`](../DEVELOPMENT_PLAN.md) — главный экран: куда движется проект, какой этап активен и что будет сделано дальше.
2. [`IDEAS.md`](IDEAS.md) — ваши идеи и результаты их критической оценки.
3. [`BUGS.md`](BUGS.md) — подтверждённые проблемы и ручные проверки.
4. [`QUESTIONS.md`](QUESTIONS.md) — решения, без которых нельзя безопасно выбрать архитектуру или дизайн.
5. [`NEXT_RELEASE.md`](NEXT_RELEASE.md) — уже завершённые изменения, которые войдут в следующий GitHub release.

## Значение статусов

- `Входящее` — идея или проблема записана, но ещё не разобрана.
- `Нужно уточнение` — без ответа владельца есть несколько существенно разных продуктов/архитектур.
- `Принято` — идея полезна, не конфликтует с проектом и может попасть в roadmap.
- `Отклонено` — идея создаёт больше вреда, дублирует существующее или не соответствует продукту; причина обязательно записывается.
- `Запланировано` — есть понятный пользовательский результат и место в этапе.
- `В работе` — выполняется один конкретный срез.
- `Нужна проверка владельца` — код готов, но требуется человеческая проверка поведения/ощущения.
- `Завершено` — критерии выполнены и проверки пройдены; запись переносится в `NEXT_RELEASE.md`.

## Как обрабатывается новая идея

Каждое содержательное сообщение владельца — входящий материал, а не автоматический приказ добавить функцию.

Агент обязан:

1. Кратко записать исходную идею в `IDEAS.md`, не искажая смысл.
2. Объяснить, какую пользовательскую проблему она решает.
3. Проверить существующий продукт: возможно, функция уже есть, сломана или планируется.
4. Критически оценить пользу, сложность, риски и соответствие local-first TTRPG-продукту.
5. Определить: принять, отложить, отклонить или задать владельцу вопрос.
6. Для принятой идеи описать самый маленький видимый срез и критерии готовности.
7. Только после этого поставить работу в `DEVELOPMENT_PLAN.md`.

Сам **анализ входящего материала** тоже является планируемой работой. Если владелец прислал большой документ, видео, референс, набор идей или противоречивые требования, в roadmap сначала появляется пункт «разобрать материал и подготовить решение», а не преждевременная реализация.

## Когда агент обязан спросить владельца

Вопрос обязателен, если выбор:

- меняет главный пользовательский workflow или место функции в UI;
- меняет формат `.md`, файлов мира, Yjs sync, permissions/privacy;
- добавляет зависимость, внешний сервис, plugin/mod API или платформенный фундамент;
- имеет два жизнеспособных варианта с разным поведением для ГМа/игрока;
- необратим или создаёт риск потери данных;
- требует вкусового решения о дизайне, которое нельзя вывести из theme system и существующих контрактов;
- противоречит ранее утверждённой идее владельца.

Вопрос должен быть коротким: контекст, 2–4 варианта, рекомендация агента и последствия каждого выбора. Пока ответа нет, допустимы только обратимые исследования, тесты и foundation-работа, не закрепляющая развилку.

## Правило завершения

После завершения среза или исправления бага:

1. Удалить его из активного этапа/списка багов.
2. Добавить понятную пользователю запись в `NEXT_RELEASE.md` в раздел `Добавлено`, `Изменено`, `Исправлено`, `Безопасность` или `Документация`.
3. Указать видимое поведение и зачем оно важно; не превращать changelog в список файлов/commit SHA.
4. Оставить в активном хранилище только незавершённые follow-up и ручную QA.
5. При публикации релиза перенести `NEXT_RELEASE.md` в версионный release changelog и создать новый чистый файл следующего релиза.

## Что где не хранить

- Подробная архитектура и технические контракты остаются в `.pi/docs/`.
- Повторяемые процедуры агента остаются в `skills/` и `.pi/rules/`.
- История завершённой работы не возвращается в roadmap/backlogs.
- Commit SHA, временные логи и сессионные отчёты не являются планом.
- Одна и та же идея не должна одновременно иметь полное описание в нескольких файлах: используйте ссылку и ID.
