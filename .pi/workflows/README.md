# Vibe workflow memory

> Дата: 2026-06-02
> Назначение: короткая, живая память для длинных срезов разработки.

## Зачем это нужно

`.pi/workflows/` хранит не общую документацию проекта, а текущий рабочий контекст: что уже решено, что сейчас делается, какие файлы нельзя трогать, какие проверки обязательны и где продолжать после compaction/нового сообщения.

Это второй уровень памяти проекта:

1. `AGENTS.md` и `.pi/skills/*` задают постоянные правила.
2. `.pi/BUG_BACKLOG.md` и `.pi/FEATURE_BACKLOG.md` хранят очередь.
3. `.pi/workflows/*` хранит живой handoff по активным длинным задачам.

Такой слой должен уменьшать количество уточняющих сообщений владельцу: агент сначала читает активный workflow, затем сам продолжает ближайший безопасный срез.

## Когда создавать workflow

Создавай или обновляй workflow-файл, если задача:

- длится больше одного небольшого turn;
- затрагивает несколько модулей или документов;
- имеет продуктовые решения владельца;
- может быть прервана compaction, лимитами git, sandbox или ручной QA;
- требует не забыть "что не трогать".

Для маленьких фиксов достаточно backlog + development plan.

## Формат файла

Рекомендуемые секции:

- `Цель` - какой результат закрывает workflow.
- `Решения владельца` - принятые продуктовые решения без повторного обсуждения.
- `Текущее состояние` - что уже сделано и проверено.
- `Нельзя трогать` - runtime/user dirty, прототипы, чувствительные файлы.
- `Следующий безопасный срез` - конкретное продолжение без вопросов.
- `Проверки` - команды и ручной QA.
- `Открытые вопросы` - только реальные блокеры, а не вкусовые мелочи.
- `Handoff note` - короткая заметка для следующего агента.

## Правило для агентов

Перед продолжением длинной задачи агент читает соответствующий workflow-файл после `AGENTS.md` и `.pi/skills/vibe-project/SKILL.md`. Если workflow устарел, агент обновляет его в том же срезе, а не держит важный контекст только в чате.
