# Hermes Project Context — Eternity Table / Vibe TTRPG Platform

Compact always-loaded Hermes context. Keep this file under 20k chars. Detailed context lives in project skills/docs and should be loaded only when relevant.

## What this is
Eternity Table (repo/codename: Vibe TTRPG Platform) is a local-first virtual tabletop and campaign knowledge base for TTRPGs: Miro/Excalidraw-like infinite canvas + Obsidian-like Markdown vault + FoundryVTT-like entities, rolls, inventory, fog of war and multiplayer.

## Stack
- Frontend: `app/` — React 19, TypeScript, Vite, Tailwind v4, Zustand, react-konva, Yjs client, Electron shell.
- Server: `server/` — Express, ws/y-websocket, chokidar, local file APIs on port 3001.
- Data: host world folder is source of truth. Entities are `.md` files with YAML frontmatter in `general/`, `gm/`, `users/`, `test-world/`.
- Sync: files ⇄ Express/Yjs ⇄ clients; debounce file writes; each canvas is a separate Y.Doc/room.

## Non-negotiable invariants
- Do not break `.md` + YAML frontmatter or `[[wiki-links]]` compatibility.
- Do not replace the unified Entity model with separate tables/models.
- Do not change canvas coordinate systems, role/permission model, or file-sync debounce without explicit owner approval.
- Do not add dependencies without explicit approval.
- UI/user-facing text: Russian first, i18n-aware. Code/types/comments: English.
- UI styles must use `app/src/utils/theme.ts`/semantic `--vibe-*` tokens or `glass.*`; avoid hardcoded surfaces.
- Use `ConfirmDialog`, not `window.confirm`.
- Respect z layers: canvas 0, pinned 10, canvas UI 20, drawer buttons 30, drawers 40, windows 50, popovers/dialogs 9999+.

## Token-saving operating mode
1. Before reading many files, query Graphify first when `graphify-out/graph.json` exists:
   - `graphify query "<question>" --budget 1500`
   - `graphify explain "<node>"`
   - `graphify path "A" "B"`
2. For exact code edits, use graph/query results to choose a small file set, then read only those files.
3. Prefer scripted summaries over dumping large files into context.
4. Keep durable project knowledge in `.pi/docs`, canonical skills, and Graphify memory, not in chat.
5. After answering a project architecture/code question using graph results, save useful Q&A back into Graphify memory when it will help future work:
   `graphify save-result --question "..." --answer "..." --nodes NodeA NodeB`.

## Vibe workflow
Work in vertical slices: Mini-PRD → smallest end-to-end slice → code → focused checks → self-critique → docs/memory update. If the owner says `продолжай`, continue the nearest safe roadmap slice autonomously. Stop only for real blockers: data-loss risk, architecture change, new dependency, security/secret issue, or ambiguous product fork.
